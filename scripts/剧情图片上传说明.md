# 剧情图片上传工具

## 文件与配置

工具复用游戏已有的 `FantasyFinal.automatonPortrait.host` 图库配置，不增加依赖、不连接游戏数据库、不发送 QQ 消息。支持现有的 `generic`（multipart `file` + Bearer token）和 `imgbb`。

默认文件位置：

| 内容 | 位置 |
| --- | --- |
| 场景与图片对应清单 | `server/src/assets/game/story/illustrations/manifest.json` |
| 网页打包图片 | `web/public/assets/story/*.webp` |
| 上传断点记录 | 与清单同目录的 `upload-receipts.json` |
| 图库配置 | `server/alemon.config.yaml` |

图片应为经过检查的静态 WebP，每张不超过 2 MiB；工具检查实际尺寸与清单一致。上传文件名由图片 SHA-256 的前 32 位生成，兼容已有 R2 Worker 的文件名约束。不会修改图片内容。

## 清单格式

```json
{
  "version": 1,
  "scenes": [
    {
      "sceneKey": "opening.F01.A.branch.2",
      "file": "opening-F01-A-branch-2.webp",
      "width": 1672,
      "height": 941,
      "alt": "当前场景的第一人称插图"
    }
  ]
}
```

`file` 只填文件名。上传成功后工具回填同一条记录的 `qqUrl`，保留其他场景、尺寸、说明和扩展字段。网页读取本地图片；QQ 读取真实图库地址。

## 在 server 目录运行

只检查配置是否完整，输出 provider、上传域名与凭据是否已填写：

```powershell
node --import tsx scripts/upload-story-images.ts --check
```

检查清单、文件、尺寸和上传断点，不上传：

```powershell
node --import tsx scripts/upload-story-images.ts
```

上传全部清单图片：

```powershell
node --import tsx scripts/upload-story-images.ts --upload
```

只上传指定场景：

```powershell
node --import tsx scripts/upload-story-images.ts --scene opening.F01.A.branch.2 --upload
```

重新检查已上传图片的公开访问：

```powershell
node --import tsx scripts/upload-story-images.ts --verify --upload
```

可用 `--config <YAML路径>`、`--manifest <清单路径>`、`--asset-dir <WebP目录>`、`--receipts <断点文件>` 指定其他位置。路径相对于运行命令时的当前目录。

生成方使用独立的同格式批次 JSON，然后通过共享锁合并，避免与上传回填同时写入：

```powershell
node --import tsx scripts/upload-story-images.ts --merge-batch src/assets/game/story/illustrations/batch-professions.json
```

合并保留其他场景；同一场景替换了文件名时，会清除旧 `qqUrl`，待新图上传验证后再回填。此操作不读取图库凭据，也不发网络请求。

## 失败后重试与更新图片

上传返回后，先保存 SHA-256 与公开 URL，再发起公开 GET 验证。只有地址返回图片内容且具有 WebP 文件签名时才回填 `qqUrl`。公网校验失败时重跑会检查已保存的 URL，避免重复上传。

相同内容会复用已上传 URL；文件内容改变则上传新的图片。旧图库图片不自动删除。每张成功结果立即保存，后面的失败不会撤销前面已成功的结果。

工具在回填前重新读取最新清单，按 `sceneKey` 合并，保留生成过程中追加的记录。上传回填和 `--merge-batch` 使用同一短时文件锁；上传期间文件名已变化则拒绝将旧 URL 写到新图记录。所有生成批次应使用 `--merge-batch`，手动直接改写清单不会遵守该锁。

图库配置与上传凭据只在服务端读取，不进入网页代码、清单或日志。工具对当前进程开启 HTTPS 证书校验，不修改系统环境。

图库地址回填后，需要重新构建 Server，部署更新后的 Server 和网页资源。构建成功不代表已部署或 QQ 客户端已验证。
